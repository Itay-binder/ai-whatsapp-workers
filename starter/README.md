# עובדי AI בווצאפ — ערכת התחלה

עובדים דיגיטליים שיושבים בווצאפ שלך. לכל עובד יש מספר ווצאפ משלו, שם, תמונה ותפקיד (למשל "נועה, קמפיינים" או "רון, סושיאל"). כותבים לו בפרטי או בקבוצת העובדים, בטקסט או בהודעה קולית, והוא עובד בשבילך עם Claude: קורא קבצים, שולף נתונים, כותב דוחות, ושולח הודעות לאחרים רק כשביקשת.

זה לא בוט שירות ללקוחות. העובד עונה **רק לך** (הבעלים). כל אחד אחר שכותב לו מקבל שתיקה.

## מה זה עושה

- **עובד = מספר ווצאפ אמיתי.** מחובר כ"מכשיר מקושר" (כמו ווצאפ ווב), עם שם, תמונה ותיאור שהשרת מגדיר לבד.
- **מוח לכל עובד.** סשן Claude (דרך Claude Agent SDK) עם קובץ תפקיד (`ROLE.md`) וזיכרון (`memory.md`). שיחה חדשה נפתחת כל יום, או כשכותבים "שיחה חדשה".
- **עונה רק לבעלים.** מספרים אחרים: התעלמות שקטה.
- **קבוצת עובדים.** בקבוצה העובד שומע הכל, אבל עונה רק כשפונים אליו: השם שלו בתחילת ההודעה, תיוג, או תגובה להודעה שלו. בהודעה קולית: "היי נועה...", "בוקר טוב צוות...".
- **הודעות קוליות.** תמלול מקומי במחשב שלך (whisper.cpp), בלי שירות בתשלום. הקלטה ארוכה או קובץ שמע שהעברת = חומר לעבודה (למשל "תסכמי לי את השיחה הזאת").
- **בלמים.** קריאה מותרת. פעולה שמשנה משהו מבקשת ממך "מאשר" או "לא" בווצאפ. שליחה, מחיקה ותשלום דרך כלים חיצוניים חסומים. אפשר לעבור למצב `bypass` (מבצע ישר ורק רושם ביומן) לעובד שסומכים עליו.
- **שליחה לאחרים לפי בקשה.** "תשלחי לאבי שהפגישה זזה ל-10" → העובד שולח מהמספר שלו ורושם ב-`sent.log`.
- **מחשב אחד בכל רגע.** אם התיקייה מסונכרנת בין שני מחשבים, `running-on.txt` מונע ריצה כפולה ומעביר את העובדים בצורה מסודרת.

## אזהרה חשובה: Baileys הוא לא ממשק רשמי

החיבור לווצאפ נעשה עם [Baileys](https://github.com/WhiskeySockets/Baileys), ספרייה לא רשמית שמתחברת כמו ווצאפ ווב. זה לא ה-API העסקי של Meta.

- **מתאים ל:** שיחה יומיומית איתך ועם הצוות שלך, ושליחה מדי פעם לאדם ספציפי לפי בקשה.
- **לא מתאים ל:** שליחה המונית, דיוור, שיווק, הודעות ללקוחות שלא ביקשו. זה מפר את תנאי השימוש של ווצאפ ו**המספר עלול להיחסם**.
- להשתמש במספרים נפרדים לעובדים, לא במספר העסקי הראשי שלך.
- מספר חדש: לתת לו כמה ימים של שימוש רגיל לפני שמבקשים ממנו לשלוח לאחרים.

אין אחריות. משתמשים על אחריותך.

## מה צריך

- מחשב שדלוק כשרוצים שהעובדים יהיו זמינים (Windows. עובד גם ב-Mac ו-Linux עם node, רק בלי סקריפטי ההתקנה של PowerShell)
- [Node.js](https://nodejs.org) גרסה 20 ומעלה (LTS)
- [Claude Code](https://claude.com/claude-code) מותקן ומחובר לחשבון שלך (המוח רץ דרכו, על המנוי שלך)
- מספר ווצאפ לכל עובד (סים נפרד או מספר וירטואלי), עם ווצאפ פעיל בפלאפון כלשהו
- לתמלול הודעות קוליות (לא חובה): whisper.cpp + ffmpeg. ב-Windows יש סקריפט שמתקין הכל.

## התחלה מהירה

**1. להוריד את הקוד**
```
git clone <כתובת הריפו>
cd starter/server
npm install
```

**2. ליצור הגדרות**
להעתיק את `workers.example.json` לתוך `server/` בשם `workers.json`, ולמלא:
- `ownerName` — השם שלך (העובדים פונים אליך בשם הזה)
- `ownerGender` — `male` או `female`
- `owner` — המספר שלך בפורמט בינלאומי בלי פלוס (למשל `972500000000`)
- `ownerPhone` — אותו מספר (לשם נשלחות בקשות אישור)
- `company` — שם העסק
- תחת `workers` — העובדים: מספר, שם, תיאור

הקובץ `workers.json` לא עולה לגיטהאב (הוא ב-`.gitignore`).

**3. תפקיד לכל עובד**
לכל עובד תיקייה `workers/<id>/` עם `ROLE.md` ו-`memory.md`. יש דוגמה מלאה ב-`workers/noa/`. לעובד חדש: להעתיק את `ROLE-TEMPLATE.md` ולמלא את התפקיד. (או להשתמש בסקיל `skills/onboard-worker` ב-Claude Code, שעושה את זה איתך.)

**4. לחבר את המספר**
```
node index.js
```
לפתוח בדפדפן `http://localhost:3100`. בפלאפון של העובד: ווצאפ ← הגדרות ← מכשירים מקושרים ← קישור מכשיר ← לסרוק את ה-QR. או ללחוץ "קבל קוד צימוד" ולהקליד את הקוד בפלאפון.

**5. לבדוק**
לכתוב לעובד בפרטי מהמספר שלך: "היי, מה התפקיד שלך?". הוא אמור לענות תוך כמה שניות.

**6. להשאיר רץ תמיד (Windows)**
```
powershell -ExecutionPolicy Bypass -File install.ps1
```
יוצר משימה מתוזמנת שמפעילה את השרת בכל כניסה למחשב ומקימה אותו מחדש אם נפל. להסרה: `install.ps1 -Remove`. ב-Mac/Linux: להריץ את `node index.js` עם pm2 או systemd.

**7. תמלול קולי (לא חובה, Windows)**
```
powershell -ExecutionPolicy Bypass -File install-whisper.ps1
```
מוריד whisper.cpp, מודל שטוב בעברית (כ-550MB) ו-ffmpeg. ב-Mac: `brew install whisper-cpp ffmpeg`, להוריד את המודל ולהגדיר `whisper.model`.

## פקודות בווצאפ

| מה כותבים | מה קורה |
|---|---|
| כל הודעה בפרטי | העובד מטפל |
| `נועה, ...` בקבוצה | רק נועה עונה |
| הודעה קולית | מתומללת ומטופלת כהוראה |
| הקלטה מועברת / קובץ שמע / קובץ טקסט | חומר לעבודה, העובד שואל מה לעשות איתו |
| `מאשר` / `לא` | תשובה לבקשת אישור |
| `שיחה חדשה` | מאפס את השיחה |
| `קוד רון` | מקבלים קוד צימוד לחיבור העובד רון מרחוק |

## הגדרות ב-workers.json

נתיבים יחסיים לתיקיית `server/`.

| שדה | מה זה |
|---|---|
| `company`, `ownerName`, `ownerGender` | שם העסק, השם שלך ומין דקדוקי (לנוסח ההודעות לעובד) |
| `owner` | רשימת מזהים שמורשים לדבר עם העובדים: המספר שלך, ולפעמים גם מזהה LID (ווצאפ משתמש בו בקבוצות. אם העובד לא עונה לך בקבוצה, לחפש בלוג את המזהה ולהוסיף) |
| `ownerPhone` | לאן נשלחות בקשות אישור כשאין שיחה פעילה |
| `names` | מזהה → שם תצוגה, לאנשים אחרים בקבוצה (רק ליומן ההקשר) |
| `group` | מזהה קבוצת העובדים (`...@g.us`). ריק = העובדים מתעלמים מכל הקבוצות |
| `groupInvite` | קישור הזמנה לקבוצה. עובד עם `joinGroup: true` מצטרף לבד |
| `port`, `pairPort` | פורט השרת (3100) ופורט דף החיבור של `pair.mjs` (3101) |
| `countryCode` | קידומת מדינה למספרים שמתחילים ב-0 (ברירת מחדל 972) |
| `timezone` | אזור זמן לחלוקת השיחות לימים |
| `workspaceDir` | התיקייה שהעובד רואה. כל קריאה, חיפוש או פקודה עם נתיב מחוץ לה (ומחוץ לתיקייה של העובד ול-`allowedDirs`) נחסמת, גם במצב bypass. ברירת מחדל `..` (תיקיית ה-starter). אפשר להגדיר גם לכל עובד בנפרד |
| `workersDir` | איפה תיקיות העובדים (`../workers`) |
| `mediaDir` | איפה נשמרות הקלטות וקבצים שהתקבלו (`../media`) |
| `allowedDirs` | תיקיות נוספות שהעובד רואה ומותר לו לכתוב בהן בלי אישור (גם לכל עובד בנפרד) |
| `preApprovedCommands` | רשימת ביטויים רגולריים לפקודות Bash שמאושרות מראש (למשל סקריפט דוח במצב בדיקה) |
| `whisper` | `exe`, `model`, `ffmpeg`, `lang` (`he` או `auto`). ריק = ברירות המחדל של install-whisper.ps1 |

לכל עובד: `phone`, `name` (המילה הראשונה = שם הפנייה), `about`, `photo`, `brain` (true = יש לו מוח), `permissions` (`bypass` או ריק), `aliases` (איותים שהתמלול עלול לכתוב לשם שלו), `joinGroup`, `pending` (השרת מדלג עליו עד שהחיבור דרך `pair.mjs` מסתיים).

## עוד כלים

- `node pair.mjs <id>` — חיבור עובד חדש בדף נפרד (`localhost:3101`), בלי לעצור את השרת הראשי. בסיום מוריד `pending` והשרת קולט את העובד.
- `GET /status` — מצב כל העובדים ב-JSON.
- `POST /send` עם `{"worker":"noa","to":"0500000003","text":"..."}` — שליחה מהמספר של עובד. בלי `to` = לקבוצה. השרת מאזין רק למחשב עצמו (127.0.0.1).

## פרטיות ואבטחה

- תיקיית `server/auth/` מכילה את מפתחות החיבור של המספרים. מי שמחזיק אותה יכול לשלוח הודעות בשמם. לא להעלות, לא לשתף.
- המוח רץ עם ההגדרות של Claude Code במחשב שלך, כולל כלי MCP שהגדרת. העובד יכול להשתמש בהם, תחת הבלמים שלמעלה. לחשוב מה העובד צריך לראות ולהגדיר `workspaceDir` בהתאם.
- תחום התיקיות נאכף ב-hook שבודק כל נתיב לפני שהכלי רץ. זו שכבת הגנה טובה, לא כספת: מידע רגיש באמת (סיסמאות, מפתחות, כספים) לא שמים מתחת לתיקייה שהעובד רואה.
- תוכן שמגיע מאחרים (הודעות בקבוצה, קבצים מועברים) מסומן לעובד כמידע ולא כהוראות. זה מקטין סיכון, לא מבטל אותו. במצב `bypass` אין בלם אנושי.

## מבנה התיקייה

```
server/            השרת: חיבור לווצאפ, ניתוב הודעות, מוח, תמלול
workers/<id>/      תפקיד, זיכרון ומצב של כל עובד
ROLE-TEMPLATE.md   תבנית תפקיד לעובד חדש
skills/            סקיל ל-Claude Code שמלווה קליטת עובד חדש
workers.example.json
```
