# עובדי AI בווצאפ — ערכת התחלה

עובדים דיגיטליים שיושבים בווצאפ שלך. לכל עובד יש מספר ווצאפ משלו, שם, תמונה ותפקיד (למשל "נועה, קמפיינים" או "רון, סושיאל"). כותבים לו בפרטי או בקבוצת העובדים, בטקסט או בהודעה קולית, והוא עובד בשבילך עם Claude: קורא קבצים, שולף נתונים מהמערכות שלך, כותב דוחות, ושולח הודעות לאחרים כשביקשת.

זה לא בוט שירות ללקוחות. העובד עונה **רק לך** (הבעלים). כל אחד אחר שכותב לו מקבל שתיקה.

## מה זה עושה

- **עובד = מספר ווצאפ אמיתי.** מחובר כ"מכשיר מקושר" (כמו ווצאפ ווב), עם שם, תמונה ותיאור שהשרת מגדיר לבד.
- **מוח לכל עובד.** סשן Claude (דרך Claude Agent SDK) עם קובץ תפקיד (`ROLE.md`) וזיכרון (`memory.md`). שיחה חדשה נפתחת כל יום, או כשכותבים "שיחה חדשה".
- **עונה רק לבעלים.** מספרים אחרים: התעלמות שקטה.
- **קבוצת עובדים.** בקבוצה העובד שומע הכל, אבל עונה רק כשפונים אליו: השם שלו בתחילת ההודעה, תיוג, או תגובה להודעה שלו. בהודעה קולית: "היי נועה...", "בוקר טוב צוות...".
- **הודעות קוליות.** תמלול מקומי במחשב שלך (whisper.cpp, עברית כברירת מחדל), בלי שירות בתשלום.
- **שני מצבי הרשאות.** `approve`: פעולה שמשנה משהו מבקשת ממך "מאשר" או "לא". `trusted`: העובד מנהל לך את המחשב ומבצע ישר, וכל פעולה נרשמת ביומן.
- **שליחה לאחרים לפי בקשה.** "תשלחי לאבי שהפגישה זזה ל-10" → העובד שולח מהמספר שלו ורושם ב-`sent.log`.
- **חיבור מערכות מהווצאפ.** שולחים לעובד שם של מערכת + מפתח API, והוא שומר את המפתח בכספת של המחשב, כותב לעצמו סקיל למערכת ובודק שהחיבור עובד.
- **תהליך התחלה.** בהודעה הראשונה העובד בודק את עצמו, ובכתיבת "התחלה" הוא מחבר GitHub, Vercel ומערכות, ושולח סיכום ✓/✗.
- **מחשב אחד בכל רגע.** אם התיקייה מסונכרנת בין שני מחשבים, `running-on.txt` מונע ריצה כפולה ומעביר את העובדים בצורה מסודרת.

## אזהרה חשובה: Baileys הוא לא ממשק רשמי

החיבור לווצאפ נעשה עם [Baileys](https://github.com/WhiskeySockets/Baileys), ספרייה לא רשמית שמתחברת כמו ווצאפ ווב. זה לא ה-API העסקי של Meta.

- **מתאים ל:** שיחה יומיומית איתך ועם הצוות שלך, ושליחה מדי פעם לאדם ספציפי לפי בקשה.
- **לא מתאים ל:** שליחה המונית, דיוור, שיווק, הודעות ללקוחות שלא ביקשו. זה מפר את תנאי השימוש של ווצאפ ו**המספר עלול להיחסם**.
- להשתמש במספרים נפרדים לעובדים, לא במספר העסקי הראשי שלך.
- מספר חדש: לתת לו כמה ימים של שימוש רגיל לפני שמבקשים ממנו לשלוח לאחרים.

אין אחריות. משתמשים על אחריותך.

## מה צריך

- מחשב Windows או Mac שדלוק כשרוצים שהעובדים יהיו זמינים (עובד גם ב-Linux עם node, בלי סקריפט התקנה)
- [Claude Code](https://claude.com/claude-code) מותקן ומחובר לחשבון שלך (המוח רץ דרכו, על המנוי שלך)
- מספר ווצאפ לכל עובד (סים נפרד או מספר וירטואלי), עם ווצאפ פעיל בפלאפון כלשהו
- כל השאר (Node.js, ffmpeg, whisper.cpp, GitHub CLI, Vercel CLI, תוסף HyperFrames) סקריפט ההתקנה מתקין לבד

לצ'קליסט מלא של הטמעה אצל לקוח: [ONBOARDING-CHECKLIST.md](ONBOARDING-CHECKLIST.md).

## התקנה

**1. להוריד את הקוד, להתקין את Claude Code ולהתחבר**
```
git clone <כתובת הריפו>
cd <הריפו>/starter
claude          (פעם אחת, להתחבר לחשבון)
```

**2. ליצור הגדרות**
להעתיק את `workers.example.json` לתוך `server/` בשם `workers.json`, ולמלא:
- `ownerName` — השם שלך (העובדים פונים אליך בשם הזה)
- `ownerGender` — `male` או `female`
- `owner` — המספר שלך בפורמט בינלאומי בלי פלוס (למשל `972500000000`)
- `ownerPhone` — אותו מספר (לשם נשלחות בקשות אישור והודעות בדיקה)
- `company` — שם העסק
- תחת `workers` — העובדים: מספר, שם, תיאור, ו-`mode` (`approve` או `trusted`)

הקובץ `workers.json` לא עולה לגיטהאב (הוא ב-`.gitignore`).

**3. תפקיד לכל עובד**
לכל עובד תיקייה `workers/<id>/` עם `ROLE.md` ו-`memory.md`. יש דוגמה מלאה ב-`workers/noa/`. לעובד חדש: להעתיק את `ROLE-TEMPLATE.md` ולמלא את התפקיד, או להשתמש בסקיל `skills/onboard-worker` ב-Claude Code.

**4א. Windows**
```
powershell -ExecutionPolicy Bypass -File server\install.ps1
```
מתקין Node.js, ffmpeg, whisper.cpp עם מודל שטוב בעברית, GitHub CLI, Vercel CLI ותוסף HyperFrames, מריץ `npm install`, ויוצר משימה מתוזמנת שמפעילה את השרת בכל כניסה ומקימה אותו מחדש אם נפל. אפשר להריץ שוב ושוב. אפשרויות: `-Lang auto` (זיהוי שפה במקום עברית), `-SkipWhisper`, `-SkipTools`, `-SkipPlugins`, ולהסרה `-Remove`.

**4ב. Mac**
```
bash install-mac.sh
```
אותו דבר דרך Homebrew, ו-LaunchAgent (`~/Library/LaunchAgents/com.ai-whatsapp-workers.server.plist`) שעולה בכל כניסה וקם לבד אם נפל. אפשרויות: `--lang auto`, `--skip-whisper`, `--skip-tools`, `--skip-plugins`, `--remove`.

בסוף הסקריפט מופיעות הוראות ל-**Full Disk Access**, וזה שלב חובה: ההרשאה ניתנת לקובץ ה-node שבאמת מריץ את השרת (הסקריפט מדפיס את הנתיב המלא ומעתיק אותו ללוח), לא ל-Terminal. בלי זה macOS חוסם בשקט קריאה של שולחן העבודה, מסמכים, הורדות ודיסקים חיצוניים. אחרי עדכון node הנתיב משתנה, ולכן מומלץ `brew pin node`. כדי שהמחשב לא יירדם, השרת מפעיל `caffeinate` כשהוא רץ, ומומלץ גם `sudo pmset -c sleep 0` (פירוט בסוף הסקריפט).

**5. לחבר את המספר**
לפתוח בדפדפן `http://localhost:3100`. בפלאפון של העובד: ווצאפ ← הגדרות ← מכשירים מקושרים ← קישור מכשיר ← לסרוק את ה-QR. או ללחוץ "קבל קוד צימוד" ולהקליד את הקוד בפלאפון.

**6. תהליך התחלה**
לכתוב לעובד בפרטי מהמספר שלך. בהודעה הראשונה הוא עונה ומריץ בדיקה עצמית: שולח לך הודעת בדיקה, כותב קובץ, בודק ffmpeg, ומבקש הודעה קולית קצרה כדי לבדוק תמלול. אחר כך כותבים **"התחלה"**, והוא ממשיך:
- מציע לחבר GitHub ו-Vercel. קוד החיבור מגיע אליך בווצאפ, ומקלידים אותו בפלאפון (github.com/login/device).
- שואל אילו מערכות לחבר (Gmail, יומן ו-Drive, Meta Ads, CRM, Canva, ClickUp, Monday ועוד) ומחבר כל אחת.
- שולח סיכום ✓/✗.

המצב נשמר ב-`workers/<id>/state/first-run.json`, כך שהתהליך לא חוזר על עצמו. "התחלה" בכל שלב ממשיך מאיפה שעצר.

הרצה ידנית בלי התקנה (לבדיקה): `cd server && npm install && node index.js`. ב-Mac/Linux יש גם `node supervise.mjs`, שמקים את השרת מחדש אם נפל.

## מצבי הרשאות

| | `approve` (ברירת מחדל) | `trusted` |
|---|---|---|
| קריאה, חיפוש, ניתוח | מבצע | מבצע |
| כתיבה בתיקייה של העובד | מבצע | מבצע |
| שליחת הודעה כשביקשת (דרך `/send` המקומי) | מבצע | מבצע |
| פעולה אחרת שמשנה משהו (קבצים, פקודות, כלי MCP) | שולח לך "אישור נדרש", מחכה ל"מאשר" / "לא" | מבצע ורושם ב-`state/approvals.log` |
| שליחה/מחיקה/תשלום דרך כלי MCP | חסום | מבצע ורושם |
| תחום תיקיות (`enforceScope`) | פעיל כברירת מחדל | כבוי כברירת מחדל (העובד מנהל את המחשב) |

איך מגדירים: `"mode": "trusted"` לעובד ב-workers.json (או ברמה הכללית). `"enforceScope": true/false` דורס את ברירת המחדל. ההגדרה הישנה `"permissions": "bypass"` עדיין עובדת ושווה ל-trusted עם תחום תיקיות פעיל.

מצב trusted הוא **לא** `--dangerously-skip-permissions` / `bypassPermissions` של Claude Code. השרת רץ במצב הרשאות רגיל, ו-hook שרץ לפני כל כלי מאשר הכל (חוץ מהבלמים למטה) ורושם. ככה המודל לא מתווכח ולא מסרב לבד, והבלמים הקשיחים נשארים.

**בלם קשיח, בשני המצבים: רק הבעלים נותן הוראות.** תוכן שלא כתבת בעצמך (הודעות של אחרים בקבוצה, ציטוט של מישהו אחר, קובץ או הקלטה שהעברת, דף אינטרנט, מיילים והודעות שהעובד קורא דרך MCP, קבצים שהתקבלו בווצאפ) הוא מידע. כשתוכן כזה נמצא בהקשר של התור הנוכחי, השרת חוסם עד סוף התור שלוש פעולות: **מחיקה**, **גישה לסודות ומפתחות**, ו**שליחה למי שאינו הבעלים** (שליחה אליך מותרת). העובד יגיד לך מה נחסם, ואם רצית את זה באמת, כותבים את הבקשה ישירות בהודעה חדשה. זו הגנה מפני מצב שבו מייל או דף אינטרנט "מבקש" מהעובד לשלוח את המפתחות שלך החוצה.

## חיבור מערכות (connect-system)

שולחים לעובד בווצאפ שם של מערכת ומפתח, למשל "תחבר את ClickUp" + הטוקן. העובד:
1. מזהה את המערכת ואת ה-API הרשמי שלה (או MCP רשמי של היצרן).
2. שומר את המפתח בכספת של מערכת ההפעלה: Windows Credential Manager או macOS Keychain. לא מחזיר אותו בתשובה, ולא כותב אותו בזיכרון, ביומן או בגיט.
3. מבקש ממך למחוק מהצ'אט את ההודעה עם המפתח.
4. כותב לעצמו סקיל למערכת ב-`systems/<שם>/SKILL.md`: נתיבים, מה מותר לקרוא, אילו כתיבות מותרות כשמבקשים, ושמחיקה אף פעם לא בלי אישור מפורש. התיקייה `systems/` לא עולה לגיט.
5. מריץ קריאה אמיתית אחת לבדיקה ומדווח מה הוא רואה.

הכלי לסודות: `server/secrets.mjs` (`set`, `run`, `has`, `list`, `delete`, `config`). `run` מריץ פקודה עם הסוד במשתנה סביבה ומסתיר אותו בפלט, כך שהמפתח לא נכנס לשיחה. עובדים עם כמה מחשבים? `node server/secrets.mjs config file` שומר את הסודות בקובץ `~/.ai-workers/secrets.json` (הרשאות 600, מסרב לשמור בתוך ריפו גיט) שאפשר לסנכרן. במקרה הזה **חובה הצפנת דיסק** בכל המחשבים (BitLocker / FileVault).

הסקיל המלא: `skills/connect-system/SKILL.md`.

## הגדרות ב-workers.json

נתיבים יחסיים לתיקיית `server/`.

| שדה | מה זה |
|---|---|
| `company`, `ownerName`, `ownerGender` | שם העסק, השם שלך ומין דקדוקי (לנוסח ההודעות לעובד) |
| `owner` | רשימת מזהים שמורשים לדבר עם העובדים: המספר שלך, ולפעמים גם מזהה LID (ווצאפ משתמש בו בקבוצות. אם העובד לא עונה לך בקבוצה, לחפש בלוג את המזהה ולהוסיף) |
| `ownerPhone` | לאן נשלחות בקשות אישור והודעות בדיקה |
| `names` | מזהה → שם תצוגה, לאנשים אחרים בקבוצה (רק ליומן ההקשר) |
| `group` | מזהה קבוצת העובדים (`...@g.us`). ריק = העובדים מתעלמים מכל הקבוצות |
| `groupInvite` | קישור הזמנה לקבוצה. עובד עם `joinGroup: true` מצטרף לבד |
| `port`, `pairPort` | פורט השרת (3100) ופורט דף החיבור של `pair.mjs` (3101) |
| `countryCode` | קידומת מדינה למספרים שמתחילים ב-0 (ברירת מחדל 972) |
| `timezone` | אזור זמן לחלוקת השיחות לימים |
| `mode` | `approve` או `trusted` לכל העובדים (אפשר גם לכל עובד בנפרד) |
| `enforceScope` | `true` = תחום תיקיות פעיל: כל נתיב מחוץ ל-`workspaceDir`, לתיקייה של העובד ול-`allowedDirs` נחסם. ברירת מחדל: פעיל ב-approve, כבוי ב-trusted |
| `workspaceDir` | התיקייה שהעובד רץ ממנה. ברירת מחדל `..` (תיקיית ה-starter). אפשר לכל עובד בנפרד |
| `workersDir` | איפה תיקיות העובדים (`../workers`) |
| `mediaDir` | איפה נשמרות הקלטות וקבצים שהתקבלו (`../media`). קריאה משם נחשבת תוכן זר |
| `allowedDirs` | תיקיות נוספות שהעובד רואה ומותר לו לכתוב בהן בלי אישור (גם לכל עובד בנפרד) |
| `preApprovedCommands` | ביטויים רגולריים לפקודות Bash שמאושרות מראש במצב approve |
| `whisper` | `exe`, `model`, `ffmpeg`, `lang` (`he` כברירת מחדל, או `auto`). ריק = ברירות המחדל של ההתקנה |
| `engine` | מנוע המוח: `claude` (ברירת מחדל). ראו "מנוע המוח" |
| `secrets` | `backend`: `os` (כספת מערכת ההפעלה, ברירת מחדל) או `file`, ו-`file`: נתיב לקובץ הסודות |

לכל עובד: `phone`, `name` (המילה הראשונה = שם הפנייה), `about`, `photo`, `brain` (true = יש לו מוח), `mode`, `enforceScope`, `engine`, `aliases` (איותים שהתמלול עלול לכתוב לשם שלו), `joinGroup`, `pending` (השרת מדלג עליו עד שהחיבור דרך `pair.mjs` מסתיים).

## מנוע המוח

היום המוח הוא Claude (דרך Claude Agent SDK). הקוד בנוי כך שאפשר להוסיף מנוע אחר:
- `server/brains.js` בוחר מנוע לפי `engine`, ומתעד את הממשק שכל מנוע חייב לממש (`ask`, `reset`, `close`, `busy`, ו-callbacks לתשובה, הקלדה ואישור).
- `server/policy.js` מכיל את כל מדיניות ההרשאות (מצבים, תוכן זר, תחום תיקיות) ולא תלוי במנוע.
- `server/brain.js` הוא מנוע Claude.

## עוד כלים

- `node pair.mjs <id>` — חיבור עובד חדש בדף נפרד (`localhost:3101`), בלי לעצור את השרת הראשי. בסיום מוריד `pending` והשרת קולט את העובד.
- `GET /status` — מצב כל העובדים ב-JSON.
- `POST /send` עם `{"worker":"noa","to":"0500000003","text":"..."}` — שליחה מהמספר של עובד. בלי `to` = לקבוצה. השרת מאזין רק למחשב עצמו (127.0.0.1).
- `node secrets.mjs ...` — הכספת (ראו למעלה).
- `node supervise.mjs` — מריץ את השרת ומקים אותו מחדש אם נפל (מה שה-LaunchAgent מפעיל ב-Mac).

## פרטיות ואבטחה

- **רק הבעלים נותן הוראות.** הודעות ממספרים אחרים לא מגיעות למוח בכלל. תוכן מאחרים שכן נכנס להקשר (קבוצה, קבצים מועברים, רשת, מייל) מסומן כמידע, ובתור שבו הוא נמצא נחסמות מחיקה, גישה לסודות ושליחה לאחרים. זה מקטין סיכון משמעותית, לא מבטל אותו.
- **סודות בכספת של מערכת ההפעלה.** לא בקבצים בתיקיית העבודה, לא בזיכרון ולא בגיט. היומן `approvals.log` מסתיר מחרוזות שנראות כמו מפתחות. שימו לב: הודעה ששלחת עם מפתח נשמרת גם ביומני השיחה של Claude Code במחשב (`~/.claude/projects`), ולכן המחשב עצמו צריך להיות מוגן בסיסמה.
- **הצפנת דיסק** (BitLocker ב-Windows, FileVault ב-Mac) מומלצת תמיד, וחובה כשמסנכרנים סודות או את תיקיית העובדים בין מחשבים.
- תיקיית `server/auth/` מכילה את מפתחות החיבור של המספרים. מי שמחזיק אותה יכול לשלוח הודעות בשמם. לא להעלות, לא לשתף.
- המוח רץ עם ההגדרות של Claude Code במחשב שלך, כולל כלי MCP שהגדרת. במצב trusted העובד יכול להשתמש בכולם בלי לשאול. לבחור trusted רק לעובד שאתה סומך עליו ורוצה שינהל לך את המחשב.
- תחום התיקיות (`enforceScope`) הוא שכבת הגנה טובה, לא כספת: מידע רגיש באמת לא שמים מתחת לתיקייה שהעובד רואה.
