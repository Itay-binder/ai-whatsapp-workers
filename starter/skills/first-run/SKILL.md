# תהליך התחלה

המטרה: שהבעלים יידע תוך כמה דקות מה עובד, מה לא, ומה עוד צריך לחבר. בלי חזרות: כל שלב נרשם בקובץ המצב.

נתיבים: `<starter>` = `{{STARTER_DIR}}` בתפקיד, `<תיקיית העובד>` = `{{WORKER_DIR}}`.

## קובץ המצב
`<תיקיית העובד>/state/first-run.json`. השרת יוצר אותו בהודעה הראשונה. לקרוא אותו לפני כל שלב ולעדכן אחרי כל שלב (Write):

```json
{
  "status": "started | done",
  "steps": {
    "send": "ok | fail: <סיבה>",
    "file": "ok | fail",
    "ffmpeg": "ok | fail",
    "voice": "ok | fail | pending",
    "github": "ok | skip | fail | pending",
    "vercel": "ok | skip | fail | pending",
    "systems": { "clickup": "ok", "meta-ads": "pending" }
  },
  "summarySent": "<תאריך>"
}
```

שלב שכבר `ok` או `skip` לא חוזרים עליו. כשהבעלים כותב "התחלה" אחרי שהכל `done`: לשלוח את הסיכום הקיים ולשאול מה לבדוק או לחבר מחדש.

## איך מתחילים
- *הודעה ראשונה (אוטומטי):* לענות בקצרה להודעה עצמה, לבצע רק את שלב א, לשלוח את התוצאה ולהציע: "רוצה שנמשיך לחבר את GitHub, Vercel והמערכות שלך? לכתוב התחלה".
- *"התחלה":* להמשיך מהשלב הראשון שאינו `ok`/`skip`, עד הסוף.
- הודעות ביניים קצרות. לא להציף. שלב שמחכה לבעלים (קוד, החלטה) = לשאול ולעצור את התור. ממשיכים כשהוא עונה.

## שלב א: בדיקה עצמית
1. *שליחת ווצאפ לבעלים* דרך השרת המקומי, בדיוק כמו בתפקיד: Write ל-`<תיקיית העובד>/state/out.json` עם `{"worker":"<id>","to":"<OWNER_PHONE>","text":"בדיקה: אני יכול לשלוח לך הודעות מהמספר שלי."}`, ואז ה-curl מהתפקיד. `"ok":true` = ok.
2. *כתיבת קובץ:* Write ל-`<תיקיית העובד>/state/selftest.txt` עם התאריך, ואז Read. תואם = ok.
3. *ffmpeg:* `ffmpeg -version`. שורה ראשונה עם מספר גרסה = ok. אם לא נמצא: fail, וההמלצה היא להריץ שוב את ההתקנה (install.ps1 / install-mac.sh).
4. *תמלול:* לבקש מהבעלים: "תשלח לי הודעה קולית קצרה, משהו כמו בדיקה אחת שתיים". סמן `pending`. כשמגיעה הודעה קולית שתומללה (השרת מסמן אותה "שלח לך הודעה קולית"), לסמן ok ולצטט מה שמעת. אם השרת דיווח "לא הצלחתי לתמלל", לסמן fail עם השגיאה.

## שלב ב: GitHub ו-Vercel (להציע, לא לכפות)
לשאול: "לחבר גם GitHub ו-Vercel? זה נותן לי לשמור קוד ולהעלות אתרים בשבילך. כן / לא / רק אחד". לא = `skip`.

*GitHub:*
1. `gh --version`. לא מותקן: fail עם הוראה (Windows: `winget install GitHub.cli`, Mac: `brew install gh`).
2. `gh auth status`. כבר מחובר = ok, לציין לאיזה משתמש.
3. אחרת: להריץ ברקע (Bash עם run_in_background) `gh auth login --web --hostname github.com --git-protocol https < /dev/null > "<תיקיית העובד>/state/gh-login.log" 2>&1`. אחרי כ-10 שניות לקרוא את הלוג ולמצוא את הקוד החד פעמי (בפורמט XXXX-XXXX). אין קוד בלוג = fail, ולצטט לבעלים את מה שכתוב בו.
4. לשלוח לבעלים בווצאפ (דרך /send, כדי שיגיע מיד ולא בסוף התור): "לחיבור GitHub: להיכנס ל-https://github.com/login/device ולהקליד את הקוד <קוד>. תקף כ-15 דקות."
5. לחכות בפקודה אחת עם לולאה (timeout של 9 דקות): `for i in $(seq 1 18); do gh auth status >/dev/null 2>&1 && echo CONNECTED && break; sleep 30; done`. הצליח = ok. לא הצליח = `pending`, ולכתוב לבעלים שכשיסיים להקליד את הקוד, יכתוב "התחלה" ונבדוק שוב.

*Vercel:*
1. `vercel --version`. לא מותקן: fail עם הוראה (`npm i -g vercel`).
2. `vercel whoami`. מחובר = ok.
3. אחרת: ברקע `vercel login < /dev/null > "<תיקיית העובד>/state/vercel-login.log" 2>&1`, לקרוא מהלוג את הקישור והקוד (vercel.com/oauth/device...), ולשלוח לבעלים בווצאפ באותה צורה. לחכות באותה לולאה עם `vercel whoami`.
4. אם הגרסה המקומית מבקשת בחירה אינטראקטיבית (מייל / GitHub) במקום קישור: לעצור את התהליך, לסמן fail, ולכתוב לבעלים שצריך להריץ `vercel login` פעם אחת ליד המחשב.

לעולם לא לשלוח את הקוד או הקישור לאף אחד חוץ מהבעלים.

## שלב ג: אילו מערכות לחבר
לשאול שאלה אחת עם רשימה ממוספרת, והבעלים עונה במספרים או בשמות:

1. Gmail, יומן Google, Google Drive
2. Meta Ads (פייסבוק ואינסטגרם)
3. CRM (איזה?)
4. Canva
5. ClickUp
6. Monday
7. משהו אחר (לכתוב שם)

לכל מערכת שנבחרה (לסמן `pending` ב-systems, ואחת אחרי השנייה):
- *יש מחבר רשמי ב-Claude* (Google Workspace, Canva ועוד, בהגדרות של claude.ai תחת Connectors): להסביר לבעלים לחבר משם, עם החשבון שמחובר ל-Claude Code במחשב הזה, ואחר כך לכתוב "שיחה חדשה" כדי שהכלים ייטענו. לבדוק אחר כך בקריאה אחת.
- *מפתח API* (Meta Ads דרך System User, ClickUp, Monday, רוב מערכות ה-CRM): להסביר בשתיים או שלוש שורות איפה במערכת מייצרים מפתח, ושאחרי שהוא שולח אותו בהודעה, כדאי למחוק את ההודעה. כשמגיע מפתח, לעבוד לפי `<starter>/skills/connect-system/SKILL.md`.
- מערכת שהבעלים לא רוצה עכשיו: `skip`.

## שלב ד: סיכום
כשכל השלבים ok / skip / fail (או שהבעלים ביקש לעצור), לשלוח סיכום אחד. בלי טבלאות ובלי markdown, שורה לכל דבר:

```
סיכום התחלה

✓ שליחת ווצאפ
✓ כתיבת קבצים
✓ ffmpeg
✗ תמלול: לא נמצא מודל whisper, להריץ שוב את ההתקנה
✓ GitHub (משתמש: <שם>)
- Vercel: דילגנו
✓ ClickUp
… Meta Ads: מחכה למפתח

מה נשאר: <שורה או שתיים>
```

אחר כך לעדכן `status: "done"` ו-`summarySent` בקובץ המצב, ולרשום ב-`memory.md` שורה אחת: אילו מערכות מחוברות ומתי.
