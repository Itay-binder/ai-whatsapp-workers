# קליטת עובד חדש

כל עובד = מספר ווצאפ משלו + שם + תמונה + מוח Claude עם תפקיד. כולם רצים בשרת אחד (`server/index.js`).

## איפה הכל (יחסית לתיקיית ה-starter)
- שרת: `server/` (Baileys + Claude Agent SDK, פורט מ-`port` ב-workers.json, ברירת מחדל 3100)
- הגדרות עובדים: `server/workers.json` (כל שינוי בו = השרת עולה מחדש לבד תוך כ-15 שניות, כש-run.ps1 מריץ אותו)
- תיקייה לכל עובד: `workers/<id>/` עם `ROLE.md`, `memory.md`, `state/`
- תבנית תפקיד: `ROLE-TEMPLATE.md`
- קבוצת העובדים: `group` (מזהה הקבוצה, `...@g.us`) ו-`groupInvite` (קישור הזמנה) ב-workers.json

## מה צריך מהמשתמש (לשאול רק מה שחסר)
1. מספר ווצאפ של העובד (מספר נפרד, עם ווצאפ פעיל בפלאפון כלשהו)
2. שם + תפקיד (למשל "נועה, קמפיינים")
3. תמונת פרופיל (נתיב לקובץ), לא חובה
4. מין דקדוקי (זכר/נקבה) אם לא ברור מהשם
5. מצב הרשאות: רגיל (כל פעולת כתיבה מבקשת "מאשר") או `bypass` (מבצע ישר ורק רושם ביומן). ברירת מחדל: רגיל.

## שלבים

**1. מזהה (id)** — אנגלית, אות קטנה, בלי רווחים (noa, ron). התמונה ל-`server/assets/<id>.png`.

**2. תיקיית העובד** — `workers/<id>/state/`, `memory.md` (כותרת + שורת התחלה עם תאריך), ו-`ROLE.md` מהתבנית: להחליף `{{TITLE}}`, `{{GENDER}}` (זכר/נקבה), `{{ROLE}}` (פסקת תפקיד: על מה אחראי, מאיפה שולף נתונים, עם מי עובד). לנקבה: להחליף "# אתה" ב-"# את" ו"אתה מדבר" ב"את מדברת". את `{{NAME}}`, `{{ID}}`, `{{COMPANY}}`, `{{OWNER_NAME}}`, `{{PORT}}`, `{{WORKER_DIR}}`, `{{WORKSPACE_DIR}}` להשאיר כמו שהם: השרת ממלא אותם בזמן ריצה.

**3. workers.json** — להוסיף תחת `workers`:
```json
"<id>": {
  "phone": "9725XXXXXXXX",
  "name": "<שם> <תפקיד בקצרה>",
  "about": "<תפקיד> | <שם החברה>",
  "photo": "assets/<id>.png",
  "joinGroup": true,
  "brain": true,
  "aliases": ["<שם>", "<איות חלופי שהתמלול עלול לכתוב>"],
  "pending": true
}
```
המילה הראשונה ב-`name` היא שם הפנייה בקבוצה. `pending` = השרת הראשי מדלג עליו עד שהחיבור דרך pair.mjs מסתיים. `"permissions": "bypass"` רק אם המשתמש ביקש. לכתוב את הקובץ ב-node (JSON.parse/stringify), לא ידנית.

**4. חיבור (סריקה)** — שתי דרכים:
- **מקומית (ברירת מחדל):** `node pair.mjs <id>` מתוך `server/` ברקע, והמשתמש פותח `http://localhost:3101` וסורק מהווצאפ של העובד (הגדרות ← מכשירים מקושרים ← קישור מכשיר). יש גם כפתור לקוד צימוד. בסיום הסקריפט מעדכן שם/תמונה/תיאור, מוריד את `pending` ויוצא. השרת הראשי קולט לבד.
- **מרחוק:** להסיר `pending` מיד, והמשתמש כותב לעובד שכבר מחובר בפרטי "קוד <שם>" ומקבל קוד צימוד בווצאפ.

**5. קבוצה** — אם יש `groupInvite` ב-workers.json ו-`joinGroup: true`, העובד מצטרף לבד אחרי החיבור. אחרת, מנהל הקבוצה מוסיף אותו ידנית. אחרי שהוא בקבוצה, לוודא ש-`group` מכיל את מזהה הקבוצה (השרת מתעלם מכל קבוצה אחרת).

**6. אימות לפני "סיימתי"** — ב-`server/server.log`: שורה `[<id>] מחובר`. ואז לבקש מהמשתמש לכתוב לעובד בפרטי ולוודא שהוא עונה.

## הרשאות (קבוע לכל העובדים, בקוד)
- עונה רק לבעלים (המספרים וה-LID ב-`owner`). כל אחד אחר: התעלמות שקטה.
- בקבוצה: עונה רק כשההודעה מתחילה בשם שלו, מתייגים אותו, או מגיבים להודעה שלו. בהודעה קולית: כשהשם שלו (או "כולם"/"צוות") בתחילת הדיבור. מקשיב לכל השאר כהקשר.
- מצב רגיל: קריאה מותרת, כתיבה מחוץ לתיקייה שלו ומחוץ ל-`allowedDirs` מבקשת "מאשר"/"לא" בווצאפ, שליחה/מחיקה/תשלום דרך MCP חסומים.
- `bypass`: מבצע ישר בלי לשאול, רק רושם ב-`workers/<id>/state/approvals.log`.
- שולח הודעות לאחרים רק כשהבעלים מבקש, דרך `POST localhost:<port>/send`, נרשם ב-`sent.log`. לא עונה לאף אחד.

## גוצ'ות
- אסור שהשרת ירוץ בשני מחשבים: `running-on.txt` מחזיק את שם המחשב. לא להריץ `index.js` במחשב אחד כשמחשב אחר מחזיק.
- לעצור שרת רק לפי הפורט (`Get-NetTCPConnection -LocalPort 3100`), לעולם לא לפי "כל תהליכי node" (זה הורג גם כלים אחרים).
- שינוי קוד (index.js/brain.js) לא מפעיל מחדש לבד. כדי לטעון: לשמור מחדש את workers.json, או להפעיל מחדש את המשימה.
- שם הפרופיל לפעמים נכשל מיד אחרי חיבור ראשון ("App state key not present"). יש ניסיונות חוזרים, לחכות.
- מספר חדש שמתחבר ומיד שולח הרבה הודעות עלול להיחסם. לתת לעובד חדש כמה ימים של שימוש רגיל.
