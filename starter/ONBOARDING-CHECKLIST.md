# צ'קליסט הטמעה אצל לקוח

לעבור לפי הסדר. כל סעיף מסומן רק אחרי שנבדק בפועל, לא "אמור לעבוד".

## לפני ההגעה
- [ ] מספר ווצאפ נפרד לכל עובד (סים או מספר וירטואלי), עם ווצאפ פעיל בפלאפון כלשהו. לא המספר העסקי הראשי.
- [ ] שם, תפקיד ותמונה לכל עובד (למשל נועה, קמפיינים).
- [ ] המספר של הבעלים (ממנו העובד מקבל הוראות).
- [ ] מצב הרשאות לכל עובד: `approve` (מבקש אישור על כל שינוי) או `trusted` (מנהל את המחשב בלי לשאול, רושם הכל ביומן). להסביר את ההבדל לבעלים ולקבל החלטה.
- [ ] מנוי Claude פעיל לבעלים (המוח רץ על המנוי שלו).
- [ ] מחשב שנשאר דלוק ומחובר לחשמל.

## התקנה
- [ ] להוריד את הריפו למחשב של הלקוח.
- [ ] להתקין את Claude Code, להריץ `claude` פעם אחת ולהתחבר לחשבון של הבעלים.
- [ ] להעתיק את `workers.example.json` ל-`server/workers.json` ולמלא: `ownerName`, `ownerGender`, `owner`, `ownerPhone`, `company`, והעובדים (כולל `mode`).
- [ ] ליצור `workers/<id>/ROLE.md` ו-`memory.md` לכל עובד (מ-`ROLE-TEMPLATE.md`, או עם הסקיל `onboard-worker`).
- [ ] Windows: `powershell -ExecutionPolicy Bypass -File server\install.ps1`
- [ ] Mac: `bash install-mac.sh`
- [ ] לקרוא את הסיכום בסוף ההתקנה. כל ✗ מטפלים עכשיו, לא אחר כך.

## Mac בלבד
- [ ] Full Disk Access לקובץ ה-node שהסקריפט הדפיס (לא ל-Terminal). לוודא שהמתג דולק.
- [ ] להפעיל מחדש את השרת אחרי ההרשאה: `launchctl kickstart -k gui/$(id -u)/com.ai-whatsapp-workers.server`
- [ ] שינה: "מנע שינה אוטומטית כשהצג כבוי" דולק, או `sudo pmset -c sleep 0`.
- [ ] `brew pin node`, כדי שעדכון של node לא יבטל את ההרשאה.
- [ ] FileVault דולק (חובה אם הסודות מסונכרנים בין מחשבים).

## Windows בלבד
- [ ] שינה: אף פעם, כשמחובר לחשמל.
- [ ] המשימה המתוזמנת "AI WhatsApp Workers" קיימת ורצה (Task Scheduler).
- [ ] BitLocker דולק (חובה אם הסודות מסונכרנים בין מחשבים).

## חיבור המספרים
- [ ] לפתוח `http://localhost:3100` ולחבר כל עובד: QR או קוד צימוד, מהפלאפון של המספר של העובד.
- [ ] ב-`server/server.log` מופיעה שורה `[<id>] מחובר` לכל עובד.
- [ ] שם, תמונה ותיאור התעדכנו בפרופיל של העובד (לפעמים לוקח כמה דקות).

## תהליך התחלה (מהפלאפון של הבעלים)
- [ ] הבעלים כותב לעובד בפרטי. העובד עונה ומריץ בדיקה עצמית.
- [ ] הבעלים קיבל הודעת בדיקה מהמספר של העובד (שליחה עובדת).
- [ ] הבעלים שולח הודעה קולית קצרה, והעובד מצטט נכון מה נאמר (תמלול עובד).
- [ ] הבעלים כותב "התחלה": חיבור GitHub ו-Vercel (קוד מגיע בווצאפ), ובחירת מערכות.
- [ ] לכל מערכת: הבעלים שולח שם + מפתח, העובד מאשר שנשמר בכספת ומראה נתון אמיתי מהמערכת. הבעלים מוחק את ההודעה עם המפתח.
- [ ] הבעלים קיבל סיכום ✓/✗. כל ✗ מטופל או נרשם כמשימה פתוחה.

## בדיקות הרשאות (בלי לגעת בקבצים אמיתיים של הלקוח)
- [ ] "תשלח ל<מספר של מישהו מהצוות> שזו בדיקה": ההודעה נשלחה ונרשמה ב-`state/sent.log`.
- [ ] הודעה ממספר אחר לעובד: אין תשובה בכלל.
- [ ] במצב trusted: פעולה כמו יצירת תיקייה חדשה לבדיקה בוצעה בלי לשאול, ונרשמה ב-`state/approvals.log`.
- [ ] במצב approve: אותה פעולה שלחה לבעלים "אישור נדרש".
- [ ] אסור לבדוק מחיקה או שינוי על קבצים אמיתיים של הלקוח, גם כשמצפים לחסימה. בודקים רק על תיקייה חדשה שנוצרה לבדיקה.

## מסירה
- [ ] להסביר לבעלים: רק הוא נותן הוראות. מה שכתוב בקבוצה, במייל או בקובץ מועבר הוא מידע, והעובד לא יבצע לפיו מחיקה, שליחה לאחרים או גישה לסודות.
- [ ] להסביר את הפקודות: "שיחה חדשה", "התחלה", "מאשר" / "לא", "קוד <שם>".
- [ ] להראות איפה היומנים: `workers/<id>/state/approvals.log` ו-`sent.log`.
- [ ] תיקיית `server/auth/` לא יוצאת מהמחשב ולא נכנסת לגיט (מי שמחזיק אותה שולט במספרים).
